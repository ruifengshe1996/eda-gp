# DREAMPlace 全局布局算法流程全解

依据本仓库 `dreamplace-src/dreamplace/` 源码逐行整理（Placer.py /
BasicPlace.py / NonLinearPlace.py / PlaceObj.py /
NesterovAcceleratedGradientOptimizer.py），术语见 `docs/NOTATION.md`。
本文特意记录那些论文里不写、但左右实验结论的实现细节；与本项目实验
相关的细节用 **[关键]** 标注。

## 0. 管线总览

```
Params(json) → PlaceDB(C++ 读入) → BasicPlace.__init__
  ├─ 构造 init_pos（初始化分派，见 §1）
  ├─ 构造算子集（线长/密度/预条件/合法化/详细布局/噪声/绘图…）
  └─ NonLinearPlace.__call__（全局布局主循环，见 §3–§6）
→ 宏合法化（仅含可动宏的设计）→ 贪心合法化 + Abacus 行内合法化
→ 内建详细布局（k-重排、独立集匹配、全局交换等窗口局部算子）
→ 合法性检查 → 评估 wHPWL → 写出 .gp.pl
```

## 1. 初始化阶段

**分派优先级**（`BasicPlace.__init__`）：连通性场初始化 > 均匀初始化 >
中心初始化（默认）。中心初始化：全部可动单元 x,y ~ 正态（均值=版图
中心，σ = 0.001 × 版图跨度）——即"堆成一个点"。GiFt 谱初始化走独立
算子路径。历史注记：y 段有一行对全部物理单元的无条件基准 y 覆盖，
连通性分支必须在其后显式重赋 conn_y（conn-y 缺陷的修复点）。

**填充单元（filler）** **[关键]**：面积补足到目标密度的虚拟单元，
**无条件均匀随机撒满版图**，与真实单元初始分布无关。filler 只进入
密度项、不进入线长项，但与真实单元在同一个静电场中互相排斥。

**噪声注入** **[关键]**：迭代 0 开始前对所有非固定单元加
U[−0.5, 0.5] × 单元尺寸 × `gp_noise_ratio`(0.025) 的一次性噪声——
量级为单元尺寸的 2.5%，对预制秩序无实质扰动，但它发生在初始学习率
估计**之前**（见 §3）。

**边界钳制**：每个迭代开始时 `move_boundary_op` 把越界单元拉回版图内
（硬投影，无缓冲带）。

## 2. 目标函数与梯度

- 目标 = Σ_net w_net · WA(net; γ) + λ · D(pos)。
- **WA 线长模型**：每网线每轴 (Σx·e^{x/γ}/Σe^{x/γ} − Σx·e^{−x/γ}/Σe^{−x/γ})，
  γ 大→平滑（近似质心引力）、γ 小→锐利（近似 max−min，梯度集中在
  极端引脚）。度数 > `ignore_net_degree`(100) 的巨网不计。
- **静电密度 D**：ePlace 电势能。单元+filler 栅格化为电荷，DCT 解
  泊松方程得电势与电场；每单元受力 ∝ 面积 × 局部电场。
- **梯度预条件器** **[关键]**：`grad /= max(1, 单元引脚权重和 +
  α·λ·单元面积)`，α 恒为 1（无围栏区时不自适应）。含义：引脚多/面积大
  的单元走得慢；λ 增大后密度项在预条件分母中的占比上升，所有单元
  整体减速。
- 二次密度惩罚 `quad_penalty` 默认关闭，仅在高溢出平台期被自动开启
  （见 §6）。

## 3. 迭代 0 的完整时序 **[关键]**

1. 构造模型（γ 初值 = 10 × base_gamma，见 §4）；
2. 噪声注入（±2.5% 单元尺寸）；
3. **初始学习率估计**（`estimate_initial_learning_rate`）：在当前
   初始状态求梯度 g₀，做一步**探针步** x₁ = x₀ − 0.01·g₀，再求 g₁，
   取 α₀ = ‖x₀−x₁‖₂ / ‖g₀−g₁‖₂（沿梯度射线的逆 Lipschitz 估计）。
   注意：探针位移正比于 ‖g₀‖——初始状态的梯度越大越相干，探针跳得
   越远，曲率在越远处采样；
4. 进入第一次 `one_descent_step`：先边界钳制，再发现 λ 均值为 0 →
   **此刻**调用 `initialize_density_weight`（见 §4），随后优化器出步。

## 4. 两套调度的精确形式

**λ（密度权重）**：

- **初值归一化** **[关键]**：λ₀ = `density_weight`(8×10⁻⁵) ×
  ‖∇WL(x₀)‖₁ / ‖∇D(x₀)‖₁，在（加噪后的）初始状态求值。含义：
  **无论什么初始化，t=0 时密度合力恒为线长合力的 1/12500**——即使
  起点已经密度合法，前期仍是近纯线长优化，任何铺开都会被拉回坍缩
  （"启动后一段纯线长优化强制收拢"的机制根源）。
- **更新律**（每迭代一次，HPWL 模式）：λ ← λ·μ。ΔHPWL<0（改善）时
  μ = 1.05 × max(0.9999^iter, 0.98)（≈1.03–1.05 的稳定增长）；
  ΔHPWL>0（恶化）时 μ = 1.05^(1 − ΔHPWL/350000)，钳制在 [0.95, 1.05]
  ——HPWL 大幅恶化时 λ 会**倒退**。这是一个符号驱动的乘性控制器，
  没有目标轨迹概念，是 overflow 振荡与"发散-恢复循环"的动力来源。

**γ（线长模型平滑度）**：

- base_gamma = `gamma`(4.0) × (bin 宽 + bin 高)；构造时 γ = 10 ×
  base_gamma。
- 每迭代按**当前 overflow 的瞬时映射**更新：γ = base_gamma ×
  10^((ov − 0.1)·20/9 − 1)。ov=1.0 → 系数 10（最平滑）；ov=0.6 →
  1.29；ov=0.1 → 0.1。**[关键]** 低溢出起点在 t=0 就拿到比中心
  初始化锐 ~8 倍的线长模型；overflow 回升时 γ 自动回松——这个回松
  正是发散后自我恢复的通道（实验 3 的单调包络禁掉它导致 bigblue3
  崩溃 +4.94%）。

## 5. Nesterov 优化器（ePlace Algorithm 2）

- 主序列 u_k、参考序列 v_k、动量系数 a_{k+1} = (1+√(4a_k²+1))/2；
  u_{k+1} = v_k − α_k·g(v_k)，v_{k+1} = u_{k+1} +
  ((a_k−1)/a_{k+1})·(u_{k+1} − u_k)。
- **步长 = Lipschitz 估计的"线搜索"** **[关键]**：α_{k+1} =
  ‖v_{k+1}−v_k‖/‖g_{k+1}−g_k‖，仅当 α_{k+1} > 0.95·α_k 时接受
  （最多回溯 10 次）——它接受的是曲率估计的稳定性，**不检查目标是否
  下降**，也没有任何单步位移上限。
- **BB 步长**（`use_bb="auto"`）**[关键]**：仅当设计含**可动宏**时
  启用（ISPD2005 中只有 bigblue3，2480 个可动宏）：优先取 BB 短步长
  s·y/y·y，非正则退回 min(Lipschitz, α_k)。即 bigblue3 与其余 7 个
  设计跑的是**不同的步长规则**——比较跨设计现象时的隐藏混杂因子。
- 约束函数 = 边界钳制。

## 6. 收敛控制：三层循环、停止、回滚与扰动

**循环结构**：Lgamma（外，本项目配置 1000 上限）→ Llambda（=1）→
Lsub（=1），即扁平单层循环，γ、λ 每迭代都更新。

**停止判据**（Lgamma 层）**[关键]**：`迭代 > 100` **且**
（(overflow < stop_overflow(0.07) 且本迭代 HPWL 高于上一迭代) 或
max_density < target_density）。注意三点：最少 100 迭代的硬下限；
到达目标溢出后**还要等 HPWL 出现一次回升**才停（"过冲一步"）；另有
独立的早停：50 迭代窗口内 overflow 上升且 HPWL 超过历史最优 2 倍。

**最优快照**：按**最低 overflow**（不是最优 wHPWL）记录 best_pos。

**发散检测与回滚** **[关键]**：仅在 overflow ∈ (0.077, 0.28) 带内
生效；50 迭代窗口内若 HPWL 均值高出最优 1.2×阈值，且（overflow 均值
超阈值 / overflow 平台 / overflow 频繁抖动 >60%）之一成立 → 回滚到
best_pos 并**终止全局布局**（不是重试）。阈值自适应 = 当前 overflow。

**平台期扰动** **[关键]**：overflow 在 15 迭代窗口内变化 <0.1% 且
距上次扰动 >50 迭代时——ov>0.9：开启二次密度惩罚并把 density_factor
翻倍；ov>0.95：追加**熵注入**（全体向质心收缩 ×0.996 + 高斯噪声
σ=40–90 版图单位，固定单元复原）。注意触发条件苛刻：低溢出起点的
初始化**永远不会**收到熵注入——流程中没有面向中低溢出阶段的任何
长程重排手段。

## 7. 全局布局之后

宏合法化（仅可动宏设计）→ 贪心合法化 → Abacus（行内动态规划）→
内建详细布局（k-重排 / 独立集匹配 / 全局交换 / 局部重排，窗口尺度
均为若干行×若干列的邻域）→ 合法性检查 → 评估最终 wHPWL。
**[关键]** 全部后端算子都是局部的：全局布局阶段冻结的长程秩序错误，
后端无法修复（多次实验证实，如展开对 bigblue3 的 +9.27% 一路保留到
最终结果）。
