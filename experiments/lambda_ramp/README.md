# 实验 11：λ 斜坡率 —— 初始化研究的迭代数混杂对照

> **本文件在任何 GPU 运行之前提交（预注册）。** §5 的预测在看到数据前写定，
> §6 结果区在运行后追加，不修改 §5。

## 1. 背景

本仓库十条实验线都以「相对 center 初始化的 wHPWL 变化」为质量指标，以
「全局布局迭代数」为速度指标，并据此提出了两种使用模式（
`docs/RESULTS_SUMMARY.md` §5）：**质量优先**用保序收缩（shrink001，
−0.04% @ 迭代 −1~+9%），**速度优先**用容量展开或谱初始化（obsspread
+1.82% @ 迭代 −18~34%，GiFt +1.86% @ 迭代 −25~34%）。

这套叙事默认了一个前提：**不同初始化的 wHPWL 差异来自它们给出的秩序
质量差异**。本实验检验这个前提。

## 2. 动机：一个从未被控制的混杂

把修复后主表（`docs/RESULTS_SUMMARY.md` §3）的五个变体按「几何平均
wHPWL 变化」与「迭代数相对 center 的变化」两列并排：

| 变体 | wHPWL 几何平均 | 迭代数 vs center |
|---|---|---|
| shrink001 | **−0.04%** | +4%（−1~+9） |
| obsfield | +0.34% | −10%（−4~16） |
| conn-grid | +0.40% | −10%（−5~15） |
| obsspread | +1.82% | −26%（−18~34） |
| GiFt | +1.86% | −30%（−25~34） |

两列的皮尔逊相关系数 **r = −0.967**，斜率约 **−0.063 %wHPWL / %迭代**：
迭代数用得越多，线长越好，五个变体几乎落在同一条直线上。

这带来一个替代解释：**初始化根本没有改变解的质量，它只是改变了优化器
实际跑的迭代数**；所谓「更聪明的初始化」与「更笨但跑得更久」在数据上
不可区分。若成立，本仓库全部质量结论都需要重新表述。

要区分这两种解释，需要一条**固定初始化、只改迭代数**的对照曲线。本项目
从未跑过：`grep -r PCOF experiments/` 在所有配置里零命中。

### 迭代数其实是一个未受控的超参数

`PlaceObj.py::update_density_weight_op_hpwl`（ISPD2005 无 fence region，
λ 更新实际走的是这个 RePlAce 分支）的控制律是

```
delta_hpwl < 0 : mu = 1.05 * max(0.9999^it, 0.98)   # ∈ [1.029, 1.050]
否则           : mu = 1.05 * clamp(1.05^(-Δ/350000), 0.95, 1.05)
lambda *= mu
```

`ref_hpwl = 350000` 是绝对量，而 ISPD2005 的 wHPWL 在 1e8~1e9 量级，
所以第二分支几乎总是撞下界。实测（8 个同机 center 基线）：

| 设计 | 迭代 | λ 起点 | λ 终点 | 跨越十进制位数 | 有效 μ | overflow>0.7 的迭代占比 |
|---|---|---|---|---|---|---|
| adaptec1 | 613 | 7.50e-12 | 5.81e-02 | 9.89 | 1.0380 | 59% |
| adaptec2 | 642 | 7.36e-12 | 1.03e-01 | 10.15 | 1.0372 | 60% |
| adaptec3 | 681 | 8.19e-12 | 5.43e-02 | 9.82 | 1.0339 | 61% |
| adaptec4 | 717 | 7.37e-12 | 8.07e-02 | 10.04 | 1.0329 | 53% |
| bigblue1 | 679 | 6.84e-12 | 5.17e-02 | 9.88 | 1.0342 | 56% |
| bigblue2 | 666 | 7.34e-12 | 8.15e-02 | 10.05 | 1.0355 | 48% |
| bigblue3 | 997 | 3.53e-12 | 7.80e-02 | 10.34 | 1.0243 | 42% |
| bigblue4 | 848 | 2.37e-12 | 7.47e-02 | 10.50 | 1.0290 | 55% |

两个事实：

1. **λ 在所有设计上都恰好跨越 9.8~10.5 个十进制位**——这个跨度是问题
   规模无关的常数。λ 只有一次单调爬升（adaptec1 全程 611 次更新里只有
   13 次下降），控制器的「反馈」几乎不起作用，实际是开环指数斜坡。
2. 因此 **迭代数 ≈ 位数 × ln10 / ln μ**。设计间 613→997 的迭代差异，
   主要来自有效 μ 的 1.038→1.024 波动，而 μ 的波动只是 HPWL 符号分支
   的触发频率——一个无人设定、也无人观测的量。

也就是说：**迭代数不是问题难度的涌现属性，而是 λ 斜坡率这个超参数的
直接函数**。既然如此，「某初始化省了 30% 迭代」的正确对照不是别的
初始化，而是**把 λ 斜坡直接调快 30%**。

顺带更正一处机制文档错误：`MECHANISM_ANALYSIS.md` 论证 C5 称
「bigblue3 的 ~1000 迭代大半耗在发散-恢复循环里」。查 center 基线日志
第 2235 行，第 728 迭代 overflow 已达 6.85e-2 < stop_overflow，随后
`iteration 729, ( 0, 0, 0)`、DensityWeight 归零、gamma 跳到 1.08e3 —— 这是
`NonLinearPlace.py:73` 因检出可动宏（`macro_place_flag='auto'`）把
stage 0 复制了一份，bigblue3 走的是**两段式布局**（宏布局段 728 迭代 +
标准段 267 迭代），不是发散恢复。C5 的这一条据此撤回，已在
`docs/MECHANISM_ANALYSIS.md` 标注。

## 3. 方法

新增旋钮 `density_weight_ramp_scale`（默认 1.0，缺省行为逐位不变）：

```python
mu = mu ** ramp_scale          # PlaceObj.py::update_density_weight_op_hpwl
```

对 μ 取幂而不是改 `UPPER_PCOF`，是为了**只改斜坡率、不改控制器形状**：
符号行为、上下分支的相对调制、λ 下降的可能性全部保留，等价于把
λ 轨迹在对数纵轴上整体拉伸/压缩。迭代数的一阶预期是

```
iters(s) ≈ iters(1) / s
```

因为跨越的位数是常数。取 s = 1/0.7 ≈ 1.43 即对齐 obsspread 的 −30%。

**全部运行使用 center 初始化**（`random_center_init_flag=1`），其余参数
与同机 center 基线逐字相同，只改 `density_weight_ramp_scale`。这样
初始化被完全固定，迭代数是唯一被操纵的变量。

唯一的第二处差异：`global_place_stages[0].iteration` 从 1000 提到 2000。
这是外层循环的**上限**（`PlaceObj.py:276` → `NonLinearPlace.py:626`，
不参与任何调度计算），基线设计在 613~997 迭代收敛、不触顶，故对
s ≥ 1 的臂完全惰性；提高它是为了让 s=0.70 臂（预期 bigblue4 约 1210
迭代）不被截断——若沿用 1000 的上限，慢斜坡臂会被上限伪装成「收敛」，
把 R4 变成一个测不出来的预测。

## 5. 预注册预测（写于任何 GPU 运行之前）

**R1（旋钮有效性 / 冒烟）**：iters(s) 与 iters(1)/s 的偏差在 ±15% 以内，
且对 s=2.0 也成立。若不成立，说明 λ 斜坡不是迭代数的主控量，后续预测
全部作废。

**R2（主判据 —— 速度模式是否被平凡旋钮支配）**：s=1.43 臂（迭代 −30%）
的 wHPWL 几何平均劣化 **< +1.82%**（obsspread 在同等迭代节省下的代价）。
- 若成立：初始化在速度模式上**没有独立价值**，同样的迭代节省用一行
  调度改动即可换到更便宜的质量代价，`RESULTS_SUMMARY` §5 的「速度优先」
  推荐必须撤回或改推 λ 斜坡。
- 若不成立（斜坡在 −30% 处比 +1.82% 更贵）：这是本项目第一份**铺开系
  初始化确实提供了调度换不到的东西**的正面证据，速度模式站得住。

**R3（混杂的解释力）**：把四个新数据点（s=0.7/1.0/1.43/2.0 的
几何平均 wHPWL vs 几何平均迭代数）拟合成一条曲线，五个初始化变体到这条
曲线的垂直残差**全部落在 ±0.5pp 以内**（本项目已确认的种子噪声上限，
S1/实验 4B）。
- 若成立：初始化对最终质量的贡献在噪声水平以内，**全部变体差异都由
  迭代数解释**，本仓库的核心叙事需整体改写。
- 若不成立：残差就是初始化的**真实效应量**，本实验给出本项目第一个
  去混杂后的初始化效应估计（并可能把 shrink001 的 −0.04% 变成一个更
  可信、更小或更大的数）。

**R4（慢斜坡方向）**：s=0.70 臂（迭代 +43%）的 wHPWL 几何平均 **优于**
center 基线，即 < 0%。若成立，说明基线调度是欠收敛的，shrink001 的
「冠军」地位主要来自它多跑了迭代。

**R5（bigblue3 两段式）**：bigblue3 在所有 s 上的迭代数仍近似为其余设计
的 1.5 倍，且日志中仍出现两次 `iteration N, ( 0, 0, 0)` 重启——因为两段
式来自宏布局流程而非 λ 动力学，斜坡率改不动它。
