# 实验 11：λ 斜坡率 —— 初始化研究的迭代数混杂对照

> **本文件在任何 GPU 运行之前提交（预注册）。** §5 的预测在看到数据前写定，
> §6 结果区在运行后追加，不修改 §5。

## 1. 背景

本仓库十条实验线都以「相对 center 初始化的 wHPWL 变化」为质量指标，以
「全局布局迭代数」为速度指标，并据此提出了两种使用模式（
`docs/RESULTS_SUMMARY.md` §5）：**质量优先**用保序收缩（shrink001，
−0.04% @ 迭代 −1~+9%），**速度优先**用容量展开或谱初始化（obsspread
+1.82% @ 迭代 −18~34%，GiFt +1.86% @ 迭代 −25~34%）。

这套叙事默认了一个前提：**不同初始化的 wHPWL 差异来自它们给出的秩序
质量差异**。本实验检验这个前提。

## 2. 动机：一个从未被控制的混杂

把修复后主表（`docs/RESULTS_SUMMARY.md` §3）的五个变体按「几何平均
wHPWL 变化」与「迭代数相对 center 的变化」两列并排：

| 变体 | wHPWL 几何平均 | 迭代数 vs center |
|---|---|---|
| shrink001 | **−0.04%** | +4%（−1~+9） |
| obsfield | +0.34% | −10%（−4~16） |
| conn-grid | +0.40% | −10%（−5~15） |
| obsspread | +1.82% | −26%（−18~34） |
| GiFt | +1.86% | −30%（−25~34） |

两列的皮尔逊相关系数 **r = −0.967**，斜率约 **−0.063 %wHPWL / %迭代**：
迭代数用得越多，线长越好，五个变体几乎落在同一条直线上。

这带来一个替代解释：**初始化根本没有改变解的质量，它只是改变了优化器
实际跑的迭代数**；所谓「更聪明的初始化」与「更笨但跑得更久」在数据上
不可区分。若成立，本仓库全部质量结论都需要重新表述。

要区分这两种解释，需要一条**固定初始化、只改迭代数**的对照曲线。本项目
从未跑过：`grep -r PCOF experiments/` 在所有配置里零命中。

### 迭代数其实是一个未受控的超参数

`PlaceObj.py::update_density_weight_op_hpwl`（ISPD2005 无 fence region，
λ 更新实际走的是这个 RePlAce 分支）的控制律是

```
delta_hpwl < 0 : mu = 1.05 * max(0.9999^it, 0.98)   # ∈ [1.029, 1.050]
否则           : mu = 1.05 * clamp(1.05^(-Δ/350000), 0.95, 1.05)
lambda *= mu
```

`ref_hpwl = 350000` 是绝对量，而 ISPD2005 的 wHPWL 在 1e8~1e9 量级，
所以第二分支几乎总是撞下界。实测（8 个同机 center 基线）：

| 设计 | 迭代 | λ 起点 | λ 终点 | 跨越十进制位数 | 有效 μ | overflow>0.7 的迭代占比 |
|---|---|---|---|---|---|---|
| adaptec1 | 613 | 7.50e-12 | 5.81e-02 | 9.89 | 1.0380 | 59% |
| adaptec2 | 642 | 7.36e-12 | 1.03e-01 | 10.15 | 1.0372 | 60% |
| adaptec3 | 681 | 8.19e-12 | 5.43e-02 | 9.82 | 1.0339 | 61% |
| adaptec4 | 717 | 7.37e-12 | 8.07e-02 | 10.04 | 1.0329 | 53% |
| bigblue1 | 679 | 6.84e-12 | 5.17e-02 | 9.88 | 1.0342 | 56% |
| bigblue2 | 666 | 7.34e-12 | 8.15e-02 | 10.05 | 1.0355 | 48% |
| bigblue3 | 997 | 3.53e-12 | 7.80e-02 | 10.34 | 1.0243 | 42% |
| bigblue4 | 848 | 2.37e-12 | 7.47e-02 | 10.50 | 1.0290 | 55% |

两个事实：

1. **λ 在所有设计上都恰好跨越 9.8~10.5 个十进制位**——这个跨度是问题
   规模无关的常数。λ 只有一次单调爬升（adaptec1 全程 611 次更新里只有
   13 次下降），控制器的「反馈」几乎不起作用，实际是开环指数斜坡。
2. 因此 **迭代数 ≈ 位数 × ln10 / ln μ**。设计间 613→997 的迭代差异，
   主要来自有效 μ 的 1.038→1.024 波动，而 μ 的波动只是 HPWL 符号分支
   的触发频率——一个无人设定、也无人观测的量。

也就是说：**迭代数不是问题难度的涌现属性，而是 λ 斜坡率这个超参数的
直接函数**。既然如此，「某初始化省了 30% 迭代」的正确对照不是别的
初始化，而是**把 λ 斜坡直接调快 30%**。

顺带更正一处机制文档错误：`MECHANISM_ANALYSIS.md` 论证 C5 称
「bigblue3 的 ~1000 迭代大半耗在发散-恢复循环里」。查 center 基线日志
第 2235 行，第 728 迭代 overflow 已达 6.85e-2 < stop_overflow，随后
`iteration 729, ( 0, 0, 0)`、DensityWeight 归零、gamma 跳到 1.08e3 —— 这是
`NonLinearPlace.py:73` 因检出可动宏（`macro_place_flag='auto'`）把
stage 0 复制了一份，bigblue3 走的是**两段式布局**（宏布局段 728 迭代 +
标准段 267 迭代），不是发散恢复。C5 的这一条据此撤回，已在
`docs/MECHANISM_ANALYSIS.md` 标注。

## 3. 方法

新增旋钮 `density_weight_ramp_scale`（默认 1.0，缺省行为逐位不变）：

```python
mu = mu ** ramp_scale          # PlaceObj.py::update_density_weight_op_hpwl
```

对 μ 取幂而不是改 `UPPER_PCOF`，是为了**只改斜坡率、不改控制器形状**：
符号行为、上下分支的相对调制、λ 下降的可能性全部保留，等价于把
λ 轨迹在对数纵轴上整体拉伸/压缩。迭代数的一阶预期是

```
iters(s) ≈ iters(1) / s
```

因为跨越的位数是常数。取 s = 1/0.7 ≈ 1.43 即对齐 obsspread 的 −30%。

**全部运行使用 center 初始化**（`random_center_init_flag=1`），其余参数
与同机 center 基线逐字相同，只改 `density_weight_ramp_scale`。这样
初始化被完全固定，迭代数是唯一被操纵的变量。

唯一的第二处差异：`global_place_stages[0].iteration` 从 1000 提到 2000。
这是外层循环的**上限**（`PlaceObj.py:276` → `NonLinearPlace.py:626`，
不参与任何调度计算），基线设计在 613~997 迭代收敛、不触顶，故对
s ≥ 1 的臂完全惰性；提高它是为了让 s=0.70 臂（预期 bigblue4 约 1210
迭代）不被截断——若沿用 1000 的上限，慢斜坡臂会被上限伪装成「收敛」，
把 R4 变成一个测不出来的预测。

## 5. 预注册预测（写于任何 GPU 运行之前）

**R1（旋钮有效性 / 冒烟）**：iters(s) 与 iters(1)/s 的偏差在 ±15% 以内，
且对 s=2.0 也成立。若不成立，说明 λ 斜坡不是迭代数的主控量，后续预测
全部作废。

**R2（主判据 —— 速度模式是否被平凡旋钮支配）**：s=1.43 臂（迭代 −30%）
的 wHPWL 几何平均劣化 **< +1.82%**（obsspread 在同等迭代节省下的代价）。
- 若成立：初始化在速度模式上**没有独立价值**，同样的迭代节省用一行
  调度改动即可换到更便宜的质量代价，`RESULTS_SUMMARY` §5 的「速度优先」
  推荐必须撤回或改推 λ 斜坡。
- 若不成立（斜坡在 −30% 处比 +1.82% 更贵）：这是本项目第一份**铺开系
  初始化确实提供了调度换不到的东西**的正面证据，速度模式站得住。

**R3（混杂的解释力）**：把四个新数据点（s=0.7/1.0/1.43/2.0 的
几何平均 wHPWL vs 几何平均迭代数）拟合成一条曲线，五个初始化变体到这条
曲线的垂直残差**全部落在 ±0.5pp 以内**（本项目已确认的种子噪声上限，
S1/实验 4B）。
- 若成立：初始化对最终质量的贡献在噪声水平以内，**全部变体差异都由
  迭代数解释**，本仓库的核心叙事需整体改写。
- 若不成立：残差就是初始化的**真实效应量**，本实验给出本项目第一个
  去混杂后的初始化效应估计（并可能把 shrink001 的 −0.04% 变成一个更
  可信、更小或更大的数）。

**R4（慢斜坡方向）**：s=0.70 臂（迭代 +43%）的 wHPWL 几何平均 **优于**
center 基线，即 < 0%。若成立，说明基线调度是欠收敛的，shrink001 的
「冠军」地位主要来自它多跑了迭代。

**R5（bigblue3 两段式）**：bigblue3 在所有 s 上的迭代数仍近似为其余设计
的 1.5 倍，且日志中仍出现两次 `iteration N, ( 0, 0, 0)` 重启——因为两段
式来自宏布局流程而非 λ 动力学，斜坡率改不动它。

## 6. 结果

24 次运行全部 `exit=0`，无一触发发散回滚，全部 `legal flag = 1`
（`analyze.py` 会对这两种情况打健康标记，本次为空）。基线为同机 center
（`experiments/obstacle_field/logs/center`）。

### 6.1 斜坡前沿（初始化固定为 center，只改斜坡率）

| 设计 | s=0.70 | s=1.00（基线） | s=1.43 | s=2.00 |
|---|---|---|---|---|
| adaptec1 | −0.11% (820) | 0 (613) | +0.13% (451) | +1.42% (336) |
| adaptec2 | −0.13% (901) | 0 (642) | +0.42% (479) | +0.36% (361) |
| adaptec3 | −0.24% (917) | 0 (681) | +0.69% (519) | +1.64% (398) |
| adaptec4 | −0.29% (962) | 0 (717) | +0.05% (522) | +2.03% (395) |
| bigblue1 | −0.16% (870) | 0 (679) | +0.32% (523) | +0.97% (386) |
| bigblue2 | +0.13% (887) | 0 (666) | +0.90% (491) | +2.16% (363) |
| bigblue3 | +0.02% (1296) | 0 (997) | +1.63% (743) | +5.02% (584) |
| bigblue4 | −0.22% (1128) | 0 (848) | +0.14% (628) | +3.06% (475) |
| **几何平均** | **−0.13%** | 0 | **+0.53%** | **+2.07%** |
| 迭代几何平均 | +33.4% | 0 | −25.4% | −43.7% |

**R1 成立**：迭代数确实按 1/s 缩放，三个臂与一阶预期的相对偏差分别为
−6.6%、+6.7%、+12.6%，都在 ±15% 内。λ 斜坡率就是迭代数的主控量。

前沿**强烈外凸**：头 25% 的迭代节省只要 +0.53%，再往下 18% 就要多付
1.54pp。拐点在 s≈1.43 附近。反方向的收益则很快饱和：多花 33% 迭代只
换回 −0.13%。

### 6.2 R2（主判据）：速度模式被平凡旋钮支配 —— **成立**

| | 迭代 | wHPWL |
|---|---|---|
| **λ 斜坡 s=1.43** | **−25.4%** | **+0.53%** |
| obsspread | −26.0% | +1.82% |
| GiFt | −30.0% | +1.86% |

在几乎相同的迭代节省下，λ 斜坡的质量代价是 obsspread 的 **1/3.4**
（+0.53% vs +1.82%）。逐设计看，斜坡在 8 个设计里赢 6 个，adaptec3 输
（obsspread +0.15% @ −33%），bigblue1 基本打平。两个极端值得记下：

- **adaptec4** —— 抵抗了所有初始化策略的那个设计（GiFt +2.46%、
  obsspread +1.40%）—— 在斜坡下用 −27% 的迭代只付 **+0.05%**；
- **bigblue3** —— 本项目最大的失败点（obsspread +9.27%）—— 在斜坡下
  −25% 迭代只付 **+1.63%**。

结论：`RESULTS_SUMMARY` §5 的「速度优先用 obsspread / GiFt」推荐**予以
撤回**，改为「速度优先用 `density_weight_ramp_scale`」。

### 6.3 R3（混杂的解释力）：**部分成立 —— 这是本实验最重要的结果**

各变体到本设计斜坡曲线的垂直残差（正 = 比「把 λ 斜坡调到同样迭代数」更差）：

| 设计 | conn-grid | obsfield | obsspread | GiFt | shrink001 |
|---|---|---|---|---|---|
| adaptec1 | +0.01 | −0.08 | −0.23 | +0.06 | +0.04 |
| adaptec2 | +0.40 | +0.12 | +0.74 | **−0.96** | −0.11 |
| adaptec3 | +0.09 | +0.18 | **−1.04** | **−0.62** | −0.11 |
| adaptec4 | +0.18 | +0.02 | +1.05 | +1.65 | +0.07 |
| bigblue1 | −0.05 | −0.05 | −0.40 | −0.33 | −0.00 |
| bigblue2 | +0.55 | +0.64 | +0.21 | +2.05 | −0.08 |
| bigblue3 | +0.27 | +0.19 | **+8.12** | +4.88 | −0.10 |
| bigblue4 | −0.13 | −0.13 | −0.16 | +2.08 | −0.01 |
| **几何平均** | **+0.17** | **+0.11** | **+1.00** | **+1.09** | **−0.04** |

按 ±0.5pp 的种子噪声上限判读，三类结局：

1. **conn-grid（+0.17）、obsfield（+0.11）、shrink001（−0.04）的整体
   残差都在噪声内 —— 这三种初始化相对「等迭代数的 center」没有可测效应。**
   其中 shrink001 的杀伤力最大：它是修复后数据里的「质量冠军」
   （−0.04% 几何平均），而本实验证明这个冠军头衔**完全由它多跑的
   迭代解释**，去混杂后残差恰好是 −0.04pp，且 8 个设计**逐个**都在
   ±0.11pp 内。保序收缩没有带来任何秩序上的好处，它只是让优化器跑得更久。
2. **obsspread（+1.00）与 GiFt（+1.09）的整体残差远超噪声，但符号为正**
   —— 它们不只是「便宜地换迭代」，而是相对等迭代数的 center **主动损害
   了质量**。bigblue3 的 +8.12 说明修复后仅存的那个「真实失败点」在
   去混杂后**变得更严重**，不是更轻。
3. **但残差不是均匀的**：obsspread 在 adaptec3 拿到 −1.04、bigblue1 −0.40，
   GiFt 在 adaptec2 拿到 −0.96、adaptec3 −0.62。**这些是本项目第一批
   去混杂后仍然成立的初始化正效应**，量级 0.3~1.0pp，远大于噪声。

所以 R3 的两个分支各对一半：**混杂解释了「质量模式」的全部
（shrink001/conn-grid/obsfield 归零），但没有解释掉铺开系与谱系在
少数设计上的真实效应**——只不过那些效应的整体符号是负的，正效应只
集中在 adaptec2 / adaptec3 / bigblue1 三个设计上。

### 6.4 R4（慢斜坡方向）：**成立**

s=0.70 用 +33.4% 的迭代换到 **−0.13%**，优于 center 基线，也优于原
「质量冠军」shrink001 的 −0.04%。基线调度确实是欠收敛的。但 6.3 已经
说明这不是新发现的优势，而是同一个旋钮的另一端：shrink001 的 −0.04%
本来就是「多跑 4% 迭代」的兑换值。8 个设计里 6 个受益，bigblue2
（+0.13%）与 bigblue3（+0.02%）不受益。

### 6.5 R5（bigblue3 两段式）：**成立**

bigblue3 在全部四个 s 上的迭代数都约为其余设计的 1.5 倍（743 vs ~500 @
s=1.43；584 vs ~380 @ s=2.0），且日志里稳定出现 **2 次**
`iteration N, ( 0, 0, 0)` 阶段起点（adaptec1 只有 1 次）。两段式来自宏
布局流程，斜坡率改不动它——§2 末尾对 C5 的勘误得到独立确认。

### 6.6 反思

1. **本项目十条实验线共享了一个未受控的自变量。** 迭代数不是各初始化
   的副产品，而是与质量强共线的第二个自变量（r = −0.967）。在补上固定
   初始化的斜坡曲线之前，「初始化 A 比 B 好」这句话是不可判定的。教训
   与 conn-y bug 同级，但性质不同：那次是实现错误，这次是**实验设计
   缺少对照**——所有数字都算对了，只是回答不了它们被用来回答的问题。
2. **正确的报告口径是「前沿」而不是「单点」。** 任何初始化的成绩今后
   都应报为「相对同迭代数 center 的残差」，或直接画在 6.1 的前沿图上
   （`viz/frontier.png`）。`analyze.py` 已把这个口径工具化。
3. **收敛判据本身也是一个自由度。** 前沿的存在说明 stop_overflow=0.07
   处的 wHPWL 并非「算法的能力」，而是「算法在某个未声明的迭代预算下的
   能力」。`RESULTS_SUMMARY` P4 提的 stop_overflow 扫描现在优先级上升，
   因为它和斜坡率是同一件事的两个面。
4. **幸存的研究问题变小但变清楚了**：为什么 obsspread 在 adaptec3、
   GiFt 在 adaptec2 能拿到 0.6~1.0pp 的真实正残差，而在 bigblue3 上
   分别是 +8.12 / +4.88？这是一个 n=8 上只有 3 个正例的逐设计问题，
   已不足以支撑「更好的初始化」这一主线，但足以支撑一个明确的子问题。
5. N5（λ 的 PI 目标轨迹控制器）的动机因此**改变**：原动机是「消除振荡
   省迭代」，现已证明 λ 几乎不振荡、迭代数由斜坡率单独决定。PI 控制器
   剩下的价值是**把迭代数变成用户指定的输入**（给定预算 T 自动定斜坡），
   即工程价值而非质量价值——应按这个定位重新提案。
