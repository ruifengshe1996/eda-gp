## 结论

1. **shrink001（保序收缩居中紧凑团 + 标准同伦）在质量上事实等价于 center，
   且过半设计微胜**。"center 熔化动力学不可替代 / 预制序有 +2.4% 地板"两个
   叙事均为 conn-y bug 伪影（E6 已由 e0 勘误撤销）。代价是迭代数与 center
   相当或略多（b3 +3%、b4 +9%）。
2. **迭代节省与质量分层清晰**：obsspread −30% 迭代 @ +1.8%；GiFt −30% @
   +1.9%；obsfield −12% @ +0.34%；conn-grid −11% @ +0.40%。速度-质量前沿
   的两端由 shrink001 与 obsspread 占据。
3. **bigblue3 的容量展开伤害是真实机制**（修复后仍 +9.27%）——实验 1/4 的
   "塌缩场展开破坏长程排序"结论以减半的幅度幸存；其余设计的展开代价
   ≤ +1.4%，门控问题的严重性大幅缩水。
4. 组合器重算（experiments/combiner/routing_table.md）：oracle-always
   −0.11%、oracle-or-center −0.12%，相对 always-shrink001（−0.04%）的路由
   增益仅 ~0.08pp——**修复后按设计路由的质量价值几乎消失**，路由的意义
   转向速度模式（在迭代预算约束下选变体）。
