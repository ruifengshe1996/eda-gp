# 实验 R：conn-y 缺陷与修复后全量重跑

## 背景

本项目的连通性初始化（实验 0b 起）在 `BasicPlace.py` 中接入：初始化
函数一次性算出 x、y 两个坐标。原实现在 x 段写入两者，而 `BasicPlace.py`
的 y 段有一行**无条件**用基准文件原始 y 覆盖全部物理单元的 y——
ISPD2005 基准里可动单元的原始 y 全部位于版图底行。连通性分支在 y 段
只留了一句注释错误的空操作，覆盖未被纠正。

结果：修复前所有 `connectivity_grid_init_flag=1` 的 GPU 运行，实际
测试的都是**意外变体**——"x = 连通性场分布，y = 版图底行直线"，
等效于一种从底边中线出发的点熔化。涉及实验 0b、1、2、3、6 的全部
GPU 数字与建立其上的机制叙事；GiFt、中心初始化、均匀初始化路径不受
影响。缺陷由一台 CPU 探针仪器暴露：探针复现的初始状态与真实运行的
迭代 0 数值差约 2 倍，追查到逐字节对比 `init_pos` 后定位（教训详见
实验 4 README）。

## 方法

修复为一行：y 段的连通性分支显式重新赋 conn_y（提交信息
"Fix conn-init y-clobber"，含 1 迭代探针验证：修复前 y 标准差恰为 0，
修复后场分布/收缩团几何正确）。随后对 conn 系四个变体做全量重跑，
共 33 个运行，按依赖序执行：

1. 哨兵：保序收缩 × adaptec4（历史上最难设计，先行判断方向）；
2. 连通性场 × 8 设计（地基）；
3. 保序收缩 × 其余 7 设计；
4. 障碍投影场（obsfield）× 8；
5. 障碍投影 + 容量展开（obsspread）× 8。

中心初始化基线复用既有同机运行（其代码路径修复前后逐位相同）。结果
写入独立目录（`install/fix_*_results`），修复前的意外变体数据全部
保留存档以供追溯。

## 反思：哪些叙事死了，哪些活了

**被证明是缺陷伪影的**：adaptec4 对一切非中心初始化"免疫"（修复后
保序收缩 +0.07%、obsfield +0.05%）；"预制秩序存在 +2.4% 质量地板"；
调度热身实验（实验 3）的全部否定性结论；障碍投影"大幅修复 adaptec2"
的效应量。

**穿越勘正存活的**：bigblue3 的容量展开伤害（+20.9% 腰斩为 +9.27%，
机制真实）；低 overflow 起点带来的迭代节省（obsspread −18~34%）；
GiFt 与 Jacobi 场的互不支配。

**修复后才出现的新事实**：连通性场系全线出现 5–15% 迭代节省（意外
变体没有）；保序收缩成为首个整体反超中心初始化的单一策略。

一个值得记录的讽刺：意外变体本身并不差（几何平均 +0.95%）——仅一维
场秩序加"底边点熔化"就有此成绩，它在 bigblue1 / bigblue4 上的反超还
启发了"熔化点位置"这一待验证的正式旋钮（计划中的实验 9，含注册预测：
adaptec3 的底边点熔化应胜过修复版连通性场的 +0.55%）。缺陷排查的完整
方法论教训见实验 4 README 与 `docs/NOTATION.md`。
