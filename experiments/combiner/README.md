# 实验 7：逐设计组合器 —— 路由的价值边界

## 背景

系列实验产出了多个初始化变体，且各有胜场：保序收缩（实验 6）质量最优；
容量展开系（实验 1/2 的 obsspread）与 GiFt（实验 5）省约 30% 迭代；
障碍投影场（实验 2 的 obsfield）居中。没有一个变体在所有设计上同时
最优——那么**按设计选择变体**（逐设计路由）能带来多少额外收益？上界
在哪里？

## 动机

两个目的：(1) 用**神谕口径**（每设计假想地选中已知最优变体）量化路由
的理论上界，判断投入路由器开发是否值得；(2) 若值得，寻找可计算的路由
信号——并吸取实验 4 的教训，任何候选信号先对已知结局做离线回测，
避免"看似可分实则不可分"。

## 方法与实现

`experiments/combiner/make_table.py`：从各变体的运行日志直接再生
"8 设计 × 全变体"的路由表（wHPWL 相对中心初始化、迭代数），并输出
三个口径：

- **always-X**：单一变体一用到底的几何平均；
- **神谕（全变体）**：每设计取已知最优变体；
- **神谕（含中心初始化）**：允许"该设计干脆用默认初始化"作为选项。

表格与口径完全由日志驱动，数据更新后一条命令重算。

## 结果（conn-y 缺陷修复后，即实验 R 数据）

| 口径 | 几何平均 |
|---|---|
| always-保序收缩 | **−0.04%** |
| always-obsfield | +0.34% |
| always-连通性场 | +0.40% |
| always-obsspread | +1.82% |
| always-GiFt | +1.86% |
| 神谕（全变体） | −0.11% |
| 神谕（含中心初始化） | −0.12% |

完整逐设计表见 `routing_table.md`。

## 反思

- **质量维度上，路由几乎失去意义**：单一的保序收缩（−0.04%）距离神谕
  上界（−0.12%）只差 0.08 个百分点——不值得为此维护一个按设计分派的
  机制。这个结论本身是修复重跑的礼物：缺陷勘正前的数据里各变体差异
  巨大，路由看起来必不可少；修复后地貌变平，简单方案胜出。
- **路由的真实价值转移到速度轴**：obsspread / GiFt 以 +1.8% 质量代价
  换 30% 迭代节省。合理的产品形态是两档预设（质量档 = 保序收缩，
  速度档 = obsspread），外加实验 4 标定的竞速门（两候选各跑到
  overflow ≤ 0.4 择优）供质量敏感场景使用，而非静态规则链——本实验
  曾在缺陷前数据上拟合过一条静态规则链，修复后作废，且 8 个设计拟合
  多个阈值的过拟合风险本就无法排除。
- 任何路由/预设结论的最终检验都应是**盲测**：在 ISPD2005 上冻结全部
  选择，在未见过的 ISPD2015 上零调参验证（计划中的实验 8，协议见
  `docs/RESULTS_SUMMARY.md` P2）。
