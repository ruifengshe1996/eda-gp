# 实验 3：调度热身 —— 为散开起点修正 γ/λ 入口

## 背景

DREAMPlace 的两套同伦调度都隐含"从中心聚拢态出发"的假设：密度权重 λ 的
初值按初始状态的梯度比归一（线长:密度力恒为 1 : 8×10⁻⁵，密度起步即
极弱），γ 是当前 overflow 的瞬时函数（overflow 从 1 单调下降时 γ 平滑
收紧）。散开或有序的初始化（实验 0a/0b）起步 overflow 低、状态非常规，
会遭遇失配的调度：γ 一上来就过紧（线长模型过锐、梯度集中于极端引脚），
λ 的归一化又鼓励一次"重做中心化"的塌落。

## 动机

如果散开初始化的部分损失来自调度失配而非初始化本身，那么在**调度入口**
做温和修正就应该能赎回这部分损失——这比改初始化便宜得多，且与任何
初始化正交。

## 方法与实现

三个默认关闭的旋钮：

- `gamma_warmup_iters = N`：前 N 个迭代把 overflow **视作**从 1.0 线性
  衰减（对真实值取下限 clamp），让 γ 从平滑端正常进入（`PlaceObj.
  update_gamma`）；
- `gamma_monotone_flag`：γ 系数取历史最小值的单调包络，禁止 overflow
  回弹时 γ 回松（`PlaceObj.update_gamma`）；
- `density_weight_warmup_iters = N`：推迟 λ 的乘性增长 N 个迭代
  （`NonLinearPlace`）。

变体：gmono（仅单调包络）、warm（γ 热身 100 + λ 热身 50）、warmmono
（两者叠加），以连通性场初始化为底座，在 adaptec1 / adaptec2 /
adaptec4 / bigblue3 四个设计上 A/B。

## 结果

**数据有效性**：本实验全部 GPU 运行以受 conn-y 缺陷影响的连通性初始化
为底座（意外变体），修复后**未重跑**——下述观察描述的是意外变体的行为，
结论对修复后的正确初始化是否成立仍属**悬置**。

意外变体上的观察：没有任何热身变体明确胜过不加热身的对照。gmono 使
bigblue3 恶化 +4.94%——该设计的收敛轨迹里存在多次"发散-恢复"循环，γ 的
回松正是恢复所必需，单调包络禁掉它反而致命；warm 使 adaptec2 倒退
（+2.60%）且 bigblue3 迭代数暴涨约 50%；adaptec4 在一切变体下不动。

## 反思

- 最有价值的观察是**γ 摆动是承重结构**：overflow 的非单调轨迹不是缺陷
  而是优化器的自我修复通道。这一点关于优化器动力学本身，与初始化无关，
  预计在修复后依然成立。
- "热身能赎回散开损失"的动机在修复后其实**部分失效**了：修复后的连通性
  场系变体（实验 R）本来就已接近中心初始化，没有多少损失可赎。热身
  真正值得重测的场景只剩**展开系变体**（obsspread，+1.82% 换 −30%
  迭代）：其低 overflow 起点正是调度失配论描述的对象，若热身能把 +1.82%
  压到 +0.5% 以内，"速度模式"就完整了。这是 `docs/RESULTS_SUMMARY.md`
  中优先级 P1 的内容。
